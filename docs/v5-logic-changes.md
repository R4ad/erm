# گزارش تغییر منطق بر مبنای سند مدیریت ریسک داتین نسخه ۵

## مرجع و دامنه بررسی

مرجع: `مدیریت-ریسک-داتین-v5.docx`، تاریخ درج‌شده در سند ۱۲ مهر ۱۴۰۵، دریافت‌شده از مسیر اعلامی کاربر. متن بندها و جدول‌های فایل Word بررسی شد. مبنای مقایسه کد، کامیت `f73ea67` است.

SHA-256 فایل مرجع:

```text
c6c7cc34184ba057068a12b69ecd9cda890110b06738fdc040354c8d261f42af
```

سند خود را «پیشنهادی برای تصویب» معرفی می‌کند. نرم‌افزار، تصویب سازمانی، تعیین صاحب اختیار و اجرای پایلوت میدانی را به‌جای سازمان انجام نمی‌دهد. نسخه روش آزمایشی موجود حفظ شده است؛ نامه تصویب یا داده کنترل واقعی ساخته نشده است.

## کارکرد قبلی پروژه

سامانه با Django و PostgreSQL و رابط فارسی React کار می‌کرد. کاتالوگ خدمت، مشتری، دارایی، تعهد و وابستگی؛ پرسشنامه مأموریت‌محور؛ سناریوی مرجع و نمونه ریسک؛ شواهد؛ ارزیابی؛ کنترل کیفیت؛ طرح مواجهه و اقدامات؛ پذیرش امضاشده؛ ادغام و تفکیک و سوابق ممیزی از قبل وجود داشتند.

موتور محاسبه از قبل با مدل نسخه ۵ کار می‌کرد:

- آغازگر A و قابلیت پایه B0، هرکدام ۱ تا ۵؛ اعتبار کنترل Bc از قواعد نسخه روش.
- برای هر مسیر `B = min(B0, Bc)`؛ برای سناریو بیشترین B مسیرها.
- L فقط از جدول A×B؛ I بیشترین پیامد S/D/F/C/R بین داتین و مشتریان.
- امتیاز `L×I`؛ کف تصمیم I4 حداقل متوسط و I5 حداقل بالا؛ حفظ عدد خام هنگام تصعید.
- بازه و نامعلوم، اطمینان، منع الزام‌آور و محدودیت تحمل مشتری.
- ارزیابی ذاتی، جاری و هدف جدا؛ امتیاز هدف جای جاری نمی‌نشست.

بنابراین این کار، تبدیل یک موتور CIA قدیمی به v5 نبود؛ شکاف‌های اجرایی نسخه موجود تکمیل شد.

### قواعد مهم اعتبار کنترل

ثبت E بالا به‌تنهایی موجب کاهش ریسک نمی‌شود. برای مثال، اگر شاهد یک کنترل E3 حذف شود یا آن کنترل غیرفعال شود، ارزیابی تازه آن را E1 حساب می‌کند و Bc بر اساس موانع معتبر باقی‌مانده محاسبه می‌شود. کنترل با اثر محدود اثبات‌شده می‌تواند E2 بگیرد؛ صرف ادعای وجود یا نصب کنترل نمی‌تواند.

امتیاز تأییدشده قبلی بازنویسی نمی‌شود. تعلیق یا کهنه‌شدن شاهد، کار بازبینی و ارزیابی تازه می‌خواهد. برای داده‌های قبلی نیز E2 بدون اثبات اثر، در محاسبه تازه اعتبار کاهش ندارد؛ هیچ تبدیل عددی خودکاری بین روش‌ها انجام نشده است.

### پایش و اعلان

- دوره بازبینی و فاصله ارزیابی کامل از همان نسخه روش ارزیابی خوانده می‌شود؛ پارامتر نسخه تازه تاریخ گذشته را تغییر نمی‌دهد.
- تکمیل بازبینی عادی نتیجه و اقدام بعدی می‌خواهد؛ تکمیل ارزیابی سالانه به ارزیابی جاری کامل و تأییدشده تازه وابسته است.
- رخداد مهم و شکست کنترل کلیدی حداکثر یک روز کاری؛ الزام یا تهدید تازه حداکثر پنج روز کاری؛ موعد کوتاه‌تر الزام مقدم است.
- تغییر معماری، تأمین‌کننده، وابستگی، مشتری، SLA و طبقه داده موعد بررسی پیش از تولید یا تعهد می‌خواهند.
- شکست کنترل مشترک، آزمون‌های آن کنترل را معلق و برای سایر ریسک‌های مرتبط نیز کار بازبینی ایجاد می‌کند.
- یادآوری پذیرش از پارامترهای نسخه روش می‌آید؛ برای دوره معمول ۳۰ و ۷ روز، و برای پذیرش کوتاه‌تر متناسب است. در اجرای عقب‌افتاده، مرحله جاری اعلان می‌شود.
- اقدام معوق، موعد طرح یا تصمیم، مهلت مهار، بازبینی و پرسش بی‌پاسخ به کارتابل مسئولان و نقش‌های مجاز می‌روند.
- هیچ ایمیل یا پیام بیرونی ارسال نمی‌شود. ادامه یا توقف خدمت بانکی و پذیرش یا تمدید آن خودکار نیست.

### گزارش مدیریتی

صفحه `/reports/` این موارد را نشان می‌دهد:

1. تعداد ریسک‌ها در هر سطح بر اساس آخرین ارزیابی جاری تأییدشده؛ هدف و ذاتی وارد شمارش نمی‌شوند.
2. پوشش خدمات حیاتی: بررسی دسته‌ها به‌علاوه ارزیابی جاری کامل؛ ریسک فعال بدون ارزیابی کامل مانع پوشش کامل خدمت است.
3. اقدام معوق بالا و بحرانی با مالک، خدمت و سررسید.
4. پذیرش منقضی، فاقد امضای لازم، خارج از اختیار یا وابسته به ارزیابی جایگزین‌شده.
5. کنترل کلیدی دارای E3 معتبر و مرتبط با مسیر ارزیابی جاری، با شمارش یکتای کنترل؛ کنترل مرتبط بدون آزمون معتبر در مخرج باقی می‌ماند.
6. عدم قطعیت و تمرکز وابستگی یا نقطه شکست مشترک در دامنه مجاز کاربر.
7. تغییر سطح در دوره انتخابی با جداسازی تغییر روش؛ پرونده جاری برای مشاهده تصمیم، شواهد و موعدها پیوند دارد.

گزارش، وضعیت جاری در روز اجرا را نشان می‌دهد؛ بازه تاریخ، دوره تغییرات ارزیابی را محدود می‌کند. جمع و میانگین امتیازهای ترتیبی تولید نمی‌شود. جدول جهان ریسک همچنان پوشش شناسایی دسته‌ها را نشان می‌دهد؛ شاخص مدیریتی عمداً شرط ارزیابی جاری را نیز دارد.

## تناقض داخلی سند و تصمیم پیاده‌سازی

جدول و قواعد بخش ۱۵ می‌گویند:

| مانع معتبر | Bc |
|---|---|
| فاقد اثر اثبات‌شده / E1 | ۵ |
| دست‌کم یک E2 | ۴ |
| دست‌کم یک E3 | ۳ |
| دست‌کم یک E4 یا E5 | ۲ |
| دو مانع E4/E5 مستقل | ۱ |

چند مثال سند E3 را معادل Bc=2 گرفته‌اند. پیروی هم‌زمان از جدول و این مثال‌ها ممکن نیست. مانند موتور موجود، قاعده صریح بخش ۱۵ مبناست؛ عدد برای منطبق کردن با مثال تغییر داده نشده است. تفاوت‌های امتیاز مثال‌ها با اجرای جدول:

| مثال | امتیاز نوشته‌شده در سند | نتیجه جدول بخش ۱۵ |
|---|---|---|
| EX01 هدف | ۸ | ۱۶، بحرانی |
| EX02 جاری | ۸ | ۱۲، بالا |
| EX02 هدف | ۶ | ۹، متوسط |
| EX05 جاری | ۹ | ۱۲، بالا |
| EX07 هدف | ۸ | ۱۲، بالا |
| مثال محاسبه بخش ۱۷ | ۸ | ۱۲، بالا |

این تفاوت‌ها از قبل در آزمون موتور ثبت شده بودند؛ تغییر تازه این کامیت نیستند. سایر مثال‌ها نیز با قواعد جدول ارزیابی می‌شوند، حتی وقتی تغییر B باعث تغییر L نمی‌شود.

## اجرا و مهاجرت

سه مهاجرت تازه، فیلدهای ارزیابی، اثبات اثر محدود کنترل، وضعیت انقضا و مدل‌های بازبینی و اعلان و تاریخچه آن‌ها را اضافه می‌کنند. مهاجرت‌های قبلی و نتایج تاریخی تغییر داده نشده‌اند. برای ارزیابی‌های قدیمی تصویر دامنه ساختگی ایجاد نمی‌شود؛ ثبت تصویر از تأییدهای بعدی آغاز می‌شود. ستون‌های مشتری و نام آن‌ها در پروفایل پیامد ارزیابی تأییدشده نیز از همین تصویر می‌آیند؛ افزودن مشتری یا تغییر نام بعدی، پروفایل تاریخی را گسترش نمی‌دهد.

```bash
pipenv run python manage.py migrate
pipenv run python manage.py check
pipenv run python manage.py monitor_risks
```

برای توسعه یا سرور بدون Compose، پایش پیوسته:

```bash
pipenv run python manage.py monitor_risks --watch --interval 3600
```

در Docker تولید، سرویس `monitoring` همراه پروفایل `prod` ساعتی اجرا می‌شود؛ شروع آن به بالا آمدن وب و پایان مهاجرت‌ها وابسته است. فرمان یک‌باره نیز برای cron قابل استفاده است. اعلان‌ها در `/actions/notices/` و بازبینی‌ها در «کارهای من» دیده می‌شوند. ثبت محرک از پرونده ریسک در هر دو رابط در دسترس است.

محیط اصلی داده‌های کاربر در این کار migrate یا seed نشده است؛ مهاجرت‌ها روی پایگاه داده موقت آزمون اجرا شده‌اند. برای استقرار لازم است فرمان مهاجرت یا ساخت مجدد Compose اجرا شود.

- آزمون مرورگر نمایش دامنه تاریخی و موعد هدف بدون جلسه اجباری: ۴ حالت دسکتاپ/موبایل و روشن/تیره موفق، همراه کنترل دسترس‌پذیری و نبود سرریز افقی. این آزمون رابط با API آزمایشی اجرا می‌شود؛ صحت سرور را آزمون‌های Django بررسی می‌کنند.

تصویب پارامترها، نامه اختیارها، صحت شواهد واقعی و پایلوت مستقل حداقل ۲۰ پرونده، کار سازمان است و در این تغییر به‌عنوان انجام‌شده ثبت نشده است.
