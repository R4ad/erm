# سامانه‌ی مدیریت ریسک سازمانی (ERM)

سامانه‌ی تحت وب ثبت و ارزیابی ریسک، اقدامات کاهشی، گردش کار تأیید و گزارش، با Django و PostgreSQL.
رابط کاربری فارسی و راست‌چین است و روی سرور داخلی سازمان با Docker اجرا می‌شود.

## پیش‌نیازها

- برای اجرای کامل روی سرور: Docker و Docker Compose
- برای توسعه روی سیستم خودتان: Python 3.14، pipenv و Docker (فقط برای PostgreSQL)، و Node.js 22 برای رابط React

## تنظیمات (‎.env)

همه‌ی تنظیمات از فایل ‎`.env` در ریشه‌ی پروژه خوانده می‌شود. یک نمونه‌ی توضیح‌دار در ‎`.env.example` هست:

```bash
cp .env.example .env
```

سپس دست‌کم `SECRET_KEY` و `POSTGRES_PASSWORD` را عوض کنید و همان رمز را در `DATABASE_URL` هم بگذارید.
فایل ‎`.env` در git ثبت نمی‌شود.

## اجرای کامل با Docker (سرور)

```bash
docker compose --profile prod up -d --build
```

این دستور چهار سرویس را بالا می‌آورد:

| سرویس | کار |
|---|---|
| `db` | پایگاه داده‌ی PostgreSQL 17 |
| `web` | برنامه‌ی Django با gunicorn؛ هنگام شروع، migrate و collectstatic را خودکار اجرا می‌کند |
| `monitoring` | پایش ساعتی ریسک، انقضای پذیرش و شواهد، بازبینی و اعلان داخلی؛ پس از آماده‌شدن وب شروع می‌شود |
| `nginx` | روی پورت 80 درخواست‌ها را به `web` می‌دهد و فایل‌های static را مستقیم سرو می‌کند |

سامانه روی `http://<نام سرور>/` باز می‌شود. نام سرور باید در `ALLOWED_HOSTS` باشد.
ساختن اولین کاربر مدیر:

```bash
docker compose exec web python manage.py createsuperuser
```

## توسعه روی سیستم خودتان

فقط پایگاه داده را با Docker بالا بیاورید (بدون پروفایل prod فقط `db` اجرا می‌شود):

```bash
docker compose up -d db
pipenv install --dev
pipenv run python manage.py migrate
pipenv run python manage.py createsuperuser
pipenv run python manage.py runserver
```

سامانه روی `http://127.0.0.1:8000/` باز می‌شود.

بعد از هر `git pull` یا عوض کردن شاخه، اگر `Pipfile.lock` تغییر کرده باشد دوباره `pipenv install --dev` و بعد
`migrate` را بزنید. بدون آن، بسته‌ی تازه نصب نمی‌شود و دستورها با خطایی مثل
`ModuleNotFoundError: No module named 'rest_framework'` می‌افتند. اگر virtualenv را خودتان فعال کرده‌اید، pipenv همان را
به‌کار می‌برد و بسته‌ها در همان نصب می‌شوند.

### خطای «column ... does not exist»

اگر صفحه‌ای با خطای `ProgrammingError` و «column ... does not exist» یا «relation ... does not exist» باز نشد، اول
`migrate` و بعد این دستور را بزنید:

```bash
pipenv run python manage.py migrate
pipenv run python manage.py check_schema
```

`check_schema` پایگاه داده را با مدل‌ها و مهاجرت‌ها مقایسه می‌کند و ستون یا جدول کم و زیاد، مهاجرت اجرانشده و
مهاجرتی را که اجرا شده ولی فایلش دیگر نیست، نام می‌برد.

مهاجرتی که در شاخه‌ای push شده، حتی اگر شاخه هنوز ادغام نشده، دیگر از نو ساخته یا ویرایش نمی‌شود؛ هر تغییر مدل
مهاجرت تازه می‌گیرد. پایگاهی که نسخه‌ی قبلی را اجرا کرده، آن مهاجرت را اجراشده می‌داند و نسخه‌ی تازه را هیچ‌وقت
اجرا نمی‌کند.

## رابط تازه (React)

رابط تازه‌ی سامانه در پوشه‌ی `frontend/` با React 19، TypeScript، Vite، Tailwind و Radix ساخته شده و از API جنگو
(`/api/`) می‌خواند. صفحه‌ها یکی‌یکی به آن منتقل می‌شوند؛ تا هر صفحه منتقل نشده، منو همان صفحه‌ی جنگو را باز می‌کند و
این را کنار پیوند می‌گوید. الان ورود، «کارهای من»، رجیستر و پرونده‌ی ریسک، ساخت و ویرایش ریسک و پیوندهایش، گام‌های
گردش کار، پیشنهاد و تصمیم ادغام و تفکیک، شواهد، سناریوها، دسته‌ها، جهان ریسک، پیوست و نظر، ارزیابی‌ها (پرونده‌ی ارزیابی
با کنترل کیفیت و تصمیم کارگروه، عامل آغازگر، مسیرهای تحقق، پروفایل پیامد و مقایسه)، طرح مواجهه، اقدام‌ها و پذیرش ریسک
(تأیید طرح، ثبت پیشرفت و شاهد اقدام، امضای صاحبان اختیار با نامه، لغو پذیرش و بازسنجی)، پاسخ به پرسشنامه و پرسش‌های ریسک،
تعریف پرسشنامه‌ها (سؤال با گزینه‌هایش در یک فرم)، پاسخ‌ها و بررسی عضو GRC (برگشت با سؤال، ثبت ریسک در انتظار از سناریو
یا کنار گذاشتن آن، پایان بررسی)، اعلان‌ها و بازبینی‌های پایش، کتابخانه‌ی کنترل با برگه‌ی آزمون اثربخشی (E) و
بیانیه‌ی کاربردپذیری، کاتالوگ (خدمات با تعهدها، وابستگی‌ها و مرز مسئولیت، زمان‌های بازیابی بانک‌ها و پوشش جهان ریسک؛
تعهدها، دارایی‌ها، تأمین‌کنندگان و بانک‌ها)، درخت ساختار سازمانی و صفحه‌ی روش ارزیابی در رابط تازه‌اند. طرح، توکن‌ها، کامپوننت‌ها و قاعده‌های دسترس‌پذیری و امنیت در `frontend/DESIGN.md` آمده است.

فرم‌ها و صفحه‌های خواندنی که به رابط تازه آمده‌اند قاعده‌ی تازه‌ای ندارند: `/api/forms/` و `/api/pages/` همان view
جنگوی هر صفحه را اجرا می‌کنند (`apps/api/bridge.py`)، پس دسترسی، اعتبارسنجی، پیام‌ها، ممیزی و مقصد بعد از ذخیره همان
صفحه‌ی جنگوست. اضافه کردن یک فرم دیگر یعنی یک خط در `apps/api/bridge_pages.py` و یک مسیر در
`frontend/src/app/routes.tsx`.

وقتی رابط ساخته شده باشد، `/accounts/login/` هم به صفحه‌ی ورود رابط تازه (`/app/login/`) می‌رود. ورود همان فرم و همان
سوابق ممیزی جنگو را دارد. اگر لازم شد، صفحه‌ی ورود قبلی با `/accounts/login/?classic=1` باز می‌شود.

پیش‌نیاز: Node.js 22. رابط تازه در حالت توسعه دو برنامه‌ی هم‌زمان می‌خواهد، هر کدام در یک ترمینال. ترتیب مهم است: اول
جنگو، بعد رابط.

**ترمینال ۱، جنگو** (در ریشه‌ی پروژه):

```bash
docker compose up -d db
pipenv install --dev
pipenv run python manage.py migrate
pipenv run python manage.py runserver
```

این ترمینال را باز نگه دارید. تا `runserver` اجرا نشده، رابط فقط خطای «سرور جنگو جواب نداد» نشان می‌دهد و ترمینال ۲
`http proxy error ... ECONNREFUSED 127.0.0.1:8000` می‌نویسد.

**ترمینال ۲، رابط React:**

```bash
cd frontend
npm install
npm run dev
```

حالا `http://localhost:5173/app/` را باز کنید. اول صفحه‌ی ورود رابط می‌آید و بعد از ورود به همان صفحه‌ای برمی‌گردید
که خواسته بودید. تغییرهای کد رابط بلافاصله دیده می‌شوند. همه‌ی نشانی‌های دیگر (API، صفحه‌ی ورود و صفحه‌های جنگو) از
همین آدرس به جنگو فرستاده می‌شوند. اگر جنگو روی پورت دیگری است: `DJANGO_URL=http://127.0.0.1:8001 npm run dev`.

هشدار `npm warn allow-scripts ... fsevents` روی مک را می‌توانید نادیده بگیرید؛ fsevents فقط برای دیدن تغییر فایل‌هاست
و `npm run dev` بدون اجرای اسکریپت نصب آن هم بالا می‌آید.

برای ساختن نسخه‌ای که خود جنگو سرو کند:

```bash
cd frontend
npm ci
npm run build
```

بعد از آن رابط تازه روی `http://127.0.0.1:8000/app/` هم باز می‌شود. در Docker این ساخت هنگام `docker compose build`
خودکار انجام می‌شود. جنگو این صفحه را با CSP و Trusted Types و nonce تازه برای هر درخواست می‌دهد؛ در `npm run dev`
این سیاست اعمال نمی‌شود، پس بررسی نهایی روی همین ساخت (یا آزمون‌های Playwright) است.

بررسی‌ها و تست‌های رابط (همه در `frontend/`):

```bash
npm run lint       # TypeScript، ESLint (با قاعده‌های دسترس‌پذیری) و Prettier
npm test           # Vitest و Testing Library، با axe روی هر صفحه
npm run test:e2e   # Playwright روی ساخت نهایی با همان CSP، در دسکتاپ و موبایل و هر دو تم، با axe
```

`npm run test:e2e` خودش رابط را می‌سازد و با `e2e/server.mjs` همان‌طور که جنگو می‌دهد سرو می‌کند؛ جنگو و پایگاه داده
لازم نیست. جواب‌های API در این آزمون‌ها داده‌ی آزمون (`src/test/fixtures.ts`) است و در خود برنامه هیچ داده‌ی نمایشی
نیست. اگر مرورگر Playwright روی سیستم نیست، یک بار `npx playwright install chromium` را اجرا کنید.

## تست‌ها

پایگاه داده باید بالا باشد (`docker compose up -d db`):

```bash
pipenv run pytest
```

## تنظیمات dev و prod

| فایل | چه زمانی | DEBUG |
|---|---|---|
| `config/settings/base.py` | تنظیمات مشترک | پیش‌فرض خاموش |
| `config/settings/dev.py` | `manage.py` و `pytest` روی سیستم توسعه | روشن |
| `config/settings/prod.py` | gunicorn و کانتینر Docker | خاموش |

برای انتخاب دستی، متغیر `DJANGO_SETTINGS_MODULE` را تنظیم کنید.

## ساختار پروژه

- `config/` تنظیمات و آدرس‌های اصلی
- `apps/` بخش‌های سامانه: `core`، `accounts`، `organization`، `workcalendar`، `audit`، `catalog`، `risks`، `actions`، `workflow`، `reports`،
  و `api` که API رابط React است
- `frontend/` رابط تازه با React
- `templates/` و `static/` قالب پایه، فونت وزیرمتن، Bootstrap راست‌چین و htmx
- `docker/nginx/` تنظیمات nginx
- `docs/` قواعد کسب‌وکار


## انطباق نسخه ۵ و پایش

گزارش مدیریتی در `/reports/`، اعلان‌های پایش در `/actions/notices/` و کارهای بازبینی در «کارهای من» هستند.
تغییر منطق، مرجع سند، تناقض مثال‌ها، آزمون‌ها و راهنمای مهاجرت در [گزارش تغییرات v5](docs/v5-logic-changes.md) آمده است.

در توسعه، علاوه بر migrate، برای پایش دوره‌ای اجرا کنید:

```bash
pipenv run python manage.py monitor_risks --watch --interval 3600
```

در Docker تولید، سرویس `monitoring` این کار را انجام می‌دهد. بدون `--watch` فقط یک بار اجرا می‌شود و برای cron مناسب است.
در macOS قدیمی که Chromium همراه Playwright پشتیبانی نمی‌شود، اگر Google Chrome نصب است:

```bash
cd frontend
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```
